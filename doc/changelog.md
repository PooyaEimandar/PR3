## 0.2 · 22 Nov 2026

- Steps 0.2a, 0.2b, 0.3a, 0.4a, 0.6a, 1.1 and 1.2 of the [checklist](18-delivery-checklist.md) passed on the development Mac; 0.2c, 0.3b, 0.4b and 0.6b hold what waits on the owner: the CI push, the physical phone, the model files and the Llama 3.1 licence, and the review of the vector files. Step 0.2b was split so that CBMC, which passed, and CI, which waits, show apart.
- Build and gates (FND-01): `pr3_add_module` with the layer order, `pr3_add_test` registering every test function with ctest, `pr3/poison.h`, `.clang-format`, `.clang-tidy`, `ci.yml`, and the check scripts for banned functions, layers, traps, the ledger, documentation links and freestanding symbols. New presets: `msan`, `fuzz`, `android-arm64`, `armv6m`, `rv32imc`. The `ubsan` preset adds `integer`, `bounds` and `nullability` to PR3's own targets only ([part 14](14-build-and-quality.md#building)).
- The base library (FND-03): status codes, arenas with ASan poisoning, generational pools, the buddy heap, the SPSC ring (with volatile words and fences on cores without atomics), builders, strings, UTF-8 and SipHash, with 40 tests and 128 SipHash vectors; its six CBMC harnesses verify under CBMC 6.11. A build may now choose the ring's mode with `PR3_RING_FENCED_WORDS`, which the ring harness uses because CBMC does not model Clang's C11 atomic builtins; `pr3_store_le32` and `pr3_store_le64` mask before they narrow.
- One test runner on the Mac and on Android over `adb` (FND-02), shown on the Android emulator; freestanding links for Cortex-M0+ and RV32IMC with reviewed symbol lists (FND-04). Board builds may use `float.h` and, where the core has them, atomics ([part 11](11-embedded-profiles.md#the-board-contract)).
- Canonical JSON (CORE-01): the tape parser, the correctly rounded number scanner, the canonical writer on Ryu's shortest digits, the schema-subset primitives, 23 tests, 1955 vectors generated from Python's standard library under PR3's rules, the fuzz target `fuzz_json` and a CBMC proof of the number path for inputs of up to six bytes that do not need the exact decimal. Number input is now correctly rounded rather than one multiplication by a power of ten ([part 04](04-core-runtime.md#tool-registry-and-the-schema-subset), [D-08](19-decisions-and-risks.md)); the parser's and writer's arena needs are published as `pr3_json_parse_bytes` and `pr3_json_write_bytes`; a text needing more values than its length allows is refused as invalid.
- The agent runtime (CORE-02): `pr3_core`, the sans-I/O turn with the tool registry and its schema subset, the loop guard, the history and its trimming, briefs, restore and traces, in one block the host supplies and `pr3_core_size` sizes; 50 tests; `test/vectors/core/steps.jsonl`, 61 scenarios and 2,378 calls written by `tools/gen-vectors/core_steps.py` from [part 04](04-core-runtime.md) alone and replayed by the C core byte for byte; the fuzz target `fuzz_core_step`, which runs two cores in lockstep on any script ([part 14](14-build-and-quality.md#fuzzing)); `bench_core` and the first measurement of the three `core` rows ([part 15](15-benchmarks.md#results-so-far)). Part 04 now states what the code settles: the message layout, `pr3_core_memory_report`, how long views live, the error texts, the clipping of reasons, backend names and restored text, the 8 KiB schema cap and `max_tools`, what a full session pool, heap or registry does, and the note on calls over the per-message limit. A turn that ends with calls still open, which only an abort does, answers each with `error: cancelled before its result arrived` (`PR3_CALL_CANCELLED`) and a failed trace step, so no later request shows a call without its result; the text is a constant, so ending a turn still takes no memory.
- Benchmarks: `bench/c/` with `pr3_bench.h`, the sample format of [part 15](15-benchmarks.md#module-budgets) and the json runner; workloads generated by `tools/gen-workloads.py`; the `json` row's first measurement on the Mac ([part 15](15-benchmarks.md#results-so-far)).
- [Part 14](14-build-and-quality.md#model-checking) gains a Model checking section: per-loop bounds under unwinding assertions, and why the ring and number harnesses are narrower than their code.
- Gates: `tools/check-traps.sh` refuses a `PR3_CHECK` split over lines, which its list cannot see; four such traps in the core now fit on one line and are reviewed.
- Corrections: JSON nesting is 127 levels in [part 03](03-memory-safety.md) as everywhere else; `tools/gen-vectors/` works from the specification, not from the C code ([part 13](13-project-structure.md)); Ryu's pinned commit is in [part 12](12-tech-stack.md); in [part 03](03-memory-safety.md) the step and turn lifetimes end at the next call that changes the core, and a request's messages are `pr3_message`s; parts 19 and 20 name the full-heap status `PR3_E_NOMEM`; the README's status.
- Validation: `dev`, `asan`, `ubsan`, `tsan` and `release` pass all 66 tests on the Mac with no warnings; `clang-tidy` is clean; the Android 16 emulator passes `test_base` and `test_json`; both freestanding images link with their reviewed symbols. A fuzz run that the Mac's sleep cut short (3.75 million inputs, no failure) is not counted; the hour CORE-01 asks for ran with the Mac kept awake, 50 549 773 inputs with no failure. CBMC 6.11 verifies all seven harnesses. For step 1.2: the same five presets pass all 117 tests; `clang-tidy` is clean on the core, its tests, its benchmark and its fuzz target; the core library builds for `armv6m` and `rv32imc`; ten minutes of `fuzz_core_step` on the final code ran 853 842 inputs with no failure.

## 0.1 · 21 Nov 2026

- First version of the specification: parts 01–20, from the overview and the memory model to the delivery plan, the decisions and risks, and the test ledger. Waiting for the owner's review (SPEC-01).
- Chose MLPerf Inference through MLCommons LoadGen as the official benchmark for comparisons with other projects ([D-25](19-decisions-and-risks.md)): the Edge `llama3_1-8b-edge` benchmark in SingleStream and Offline, Closed with Llama 3.1 8B Instruct and Open with PR3's pinned models. MLPerf Client was set aside. Verified results need MLCommons membership, which is the owner's decision ([D-26](19-decisions-and-risks.md)); until then every published number carries MLCommons' unverified label ([part 15](15-benchmarks.md#publishing-and-labelling)).
- Added `third_party/manifest.txt` and `tools/fetch-third-party.sh`, which fetch third-party sources at pinned commits; LoadGen 6.0.17 at `3fbc3299` is the first entry.
- Completed BEN-01 early at the owner's request: `bench/mlperf/` builds LoadGen with our CMake, wraps it in a C interface (`pr3_loadgen.h`), and adds the `pr3_mlperf` command with a loopback system under test. The CMake root, presets and warning, sanitizer and hardening modules of FND-01 are started.
- Validation: on the development Mac (Apple Clang 21, CMake 4.4), the `release` build has no warnings under the full warning set as errors. Both smoke runs reach `VALID`: SingleStream 1536 queries in 5.0 s, Offline 1280 samples in 4.2 s. They pass under `release`, `asan` and `tsan`, with eight TSan repeats. An Offline accuracy run logs one entry per sample. One race inside LoadGen's logger is suppressed for TSan instead of patched ([part 15](15-benchmarks.md#the-harness)).
