# Open decisions and risks

Most of the risk sits in three places: the bet that disciplined C is memory-safe in practice without a runtime, exact byte formats for everything the trusted side signs, hashes or sends (receipts and audit chains must verify across builds and devices), and the platform work a native SDL3 app must do itself: accessibility, complex text and input. M0 and M1 retire the first two by measurement before the app is built; M2 takes the third head on.

## Decisions

Each decision has an ID used throughout the specification. A ticked box is decided, with who decided and when; an open box shows the proposal and what settles it. Proposals are settled by the owner's review of the specification at step 0.1 unless another step is named.

- [x] **D-01 C for product code, sans-I/O.** C everywhere PR3 writes product code, as close to the bare metal as the platform allows (owner, 21 Nov 2026). A sans-I/O core that takes inputs and returns actions, a trusted side isolated from the model, hosts that do the I/O ([part 02](02-architecture.md)).
- [x] **D-02 SDL3 for the graphical app** on macOS, iOS, Android, Windows and Linux: one native program, no WebView (owner, 21 Nov 2026) ([part 10](10-app-sdl3.md)).
- [x] **D-03 Memory safety by construction, not by a runtime.** Caller-owned arenas, generational pools and a buddy heap, so safety costs no bare-metal performance (owner, 21 Nov 2026). The portable libraries have no general-purpose heap; every allocation has a lifetime from a fixed list and a bound computed at init ([part 03](03-memory-safety.md)).
- [ ] **D-04 Bounded sessions and turns.** Proposal: the core holds at most `max_sessions` (64) sessions and `max_turns` (4) turns in flight, with histories in one 8 MiB buddy heap; a full session pool evicts the least recently used idle session, which the host restores from storage; a full heap or turn pool fails the step with `PR3_E_NOMEM` and leaves the core unchanged ([part 04](04-core-runtime.md#the-history-heap)). Each limit has an edge test in the [test ledger](20-test-ledger.md#limits). Settled by step 0.1; the limits are revisited with BEN-03's measurements.
- [ ] **D-05 C17 floor, C23 where available.** Proposal: C17 is the language every compiler must accept; `<stdckdint.h>`, `[[nodiscard]]` and `counted_by` are used through `pr3/compiler.h`, with builtins or nothing as the fallback, so GCC 14 on the boards and MSVC build the same sources.
- [ ] **D-06 CMake and Ninja.** Proposal: CMake presets, one static library per module, an amalgamated `libpr3.a` for embedding; no other build system in the tree except each board's SDK wrapper and the Android Gradle project.
- [ ] **D-07 Crypto libraries.** Proposal: mbedTLS 3.6.8 LTS for SHA-256, HMAC, HKDF, P-256 ECDSA, X25519 and ChaCha20-Poly1305; the BLAKE2 authors' own C code for BLAKE2s (in neither mbedTLS nor libsodium); libsodium 1.0.22 only for SPAKE2's Edwards arithmetic in profiles that pair. Signatures are parsed with PR3's strict DER reader and verified with `mbedtls_ecdsa_verify` ([part 05](05-trusted-side.md#crypto)).
- [ ] **D-08 JSON of our own.** Proposal: a bounded tape parser and canonical writer for PR3's canonical JSON (nesting 127, last duplicate key wins, integers that fit stay integers, `-0` and other numbers as correctly rounded doubles, shortest round-trip output with Ryu, a fixed escape set), instead of a general library. Correct rounding replaced a one-multiplication conversion that could be one unit in the last place off: a canonical form must read the same on every build and device, and the cost is paid only by numbers the exact fast path cannot take (22 Nov 2026, CORE-01) ([part 04](04-core-runtime.md#tool-registry-and-the-schema-subset), [part 12](12-tech-stack.md#dropped-on-purpose)).
- [ ] **D-09 CBOR of our own.** Proposal: a bounded codec for canonical CBOR in the wire v0 messages (definite lengths, fixed field order, the `type` field first) ([part 09](09-protocol-and-hybrid.md#cbor-byte-for-byte)).
- [ ] **D-10 A UI layer of our own.** Proposal: `pr3_ui`, a small immediate-mode layer on `SDL_Renderer` with SDL3_ttf, HarfBuzz and SheenBidi, in place of Nuklear or Dear ImGui, which have no complex-script shaping or bidirectional layout ([part 10](10-app-sdl3.md#the-ui-layer)).
- [ ] **D-11 Native accessibility bridges.** Proposal: `pr3_ui` emits an accessibility tree each frame and a per-OS bridge exposes it (NSAccessibility, UIAccessibility, `AccessibilityNodeProvider`, UI Automation, AT-SPI); AccessKit is excluded because it adds a second language toolchain to the shipped app ([part 10](10-app-sdl3.md#accessibility)). Settled by APP-04 on macOS and Android.
- [ ] **D-12 The llama.cpp backend at b11429.** Proposal: llama.cpp release `b11429` (commit `d81235049384534c167caea52b85a694f6103d14`), fetched unchanged, built with recorded flags, and called through `llama.h` with no wrapper, so PR3 on the llama.cpp backend and llama.cpp alone run the same engine under LoadGen ([part 06](06-inference.md#the-llamacpp-backend)).
- [ ] **D-13 SQLCipher providers.** Proposal: SQLCipher 4.20.0 on SQLite 3.54.1 with CommonCrypto on Apple and libtomcrypt elsewhere; page size, KDF and HMAC settings pinned explicitly so a database written on one OS opens on every other. Settled by DATA-02.
- [ ] **D-14 Unicode tables from UCD 17.0.** Proposal: the character classes and case mappings the trusted side depends on are generated by `tools/gen-unicode/` from the Unicode Character Database 17.0 and checked in; a Unicode upgrade is a decision with its own vectors ([part 05](05-trusted-side.md)).
- [ ] **D-15 Golden vectors as the oracle.** Proposal: every format the trusted side signs, hashes or sends, and the core's step sequences, have golden vectors written by `tools/gen-vectors/` from the specification, independently of the C code, cross-checked against published vectors where they exist, reviewed and checked in under `test/vectors/`; they replay byte for byte on every pull request ([part 14](14-build-and-quality.md#gates)).
- [ ] **D-16 A test harness of our own.** Proposal: `test/pr3_test.h`, a header with no dependencies that runs the same tests on hosts, phones over `adb` and boards over UART.
- [ ] **D-17 A Noise implementation of our own.** Proposal: the Noise state machine for `XXpsk3` and `IK` with 25519, ChaChaPoly and BLAKE2s written for PR3 (about 400 lines) on reviewed primitives, checked against the published Noise vectors and between two PR3 builds over loopback; no C Noise library covers both patterns with these primitives and a caller-owned memory model ([part 09](09-protocol-and-hybrid.md#pairing)).
- [ ] **D-18 The app waits for events.** Proposal: SDL main callbacks with `SDL_HINT_MAIN_CALLBACK_RATE` set to `waitevent`; the app draws only when an input, a host event or an animation needs a frame, so an open window costs no CPU ([part 10](10-app-sdl3.md#structure)). Settled by APP-01's idle measurement.
- [ ] **D-19 Formal tools.** Proposal: CBMC for the base library and the parsers' arithmetic; Frama-C WP for the trusted side's validator, policy and audit chain before release; the Clang analyzer, `clang-tidy` and GCC `-fanalyzer` on every change ([part 03](03-memory-safety.md#verification)).
- [ ] **D-20 The order.** Proposal: foundations, oracles and the benchmark harness first (M0); the core and a chat on the llama.cpp backend (M1); the SDL3 app (M2); the full product (M3); the boards (M4) and the other OSes (M5) side by side; the PR3 engine (M6, startable after M1); release candidates (M7); published benchmarks and 1.0 (M8) ([roadmap](16-roadmap.md#why-this-order)).
- [ ] **D-21 Formats are versioned.** Proposal: every on-disk and on-wire format carries a version tag; a format change is a new version with its own golden vectors and a reader for the old one, never an edit of an existing vector ([part 05](05-trusted-side.md#byte-formats)).
- [ ] **D-22 C++ stays in its box.** Proposal: PR3's own sources compile as C17; C++ appears only in `bench/mlperf/` (LoadGen and its shim) and inside third-party libraries written in it (llama.cpp); `tools/check-layers.sh` fails a build where a PR3 source outside `bench/mlperf/` is compiled as C++.
- [ ] **D-23 libcurl with mbedTLS for HTTPS**, so the web reader shares the crypto library with the rest of the build ([part 08](08-tools-and-research.md)).
- [ ] **D-24 lexbor for HTML**, a spec-compliant HTML5 parser, with its allocations in a per-page PR3 region ([part 08](08-tools-and-research.md)).
- [ ] **D-25 MLPerf Inference through LoadGen as the official benchmark.** Proposal: inference is compared with other projects only through MLCommons LoadGen 6.0.17 (pinned by commit), on the Edge `llama3_1-8b-edge` benchmark in SingleStream and Offline, Closed with Llama 3.1 8B Instruct and Open with PR3's pinned models; MLPerf Client is not used because it bundles vendor execution providers with no plug-in point for another engine, has no Android build and is ONNX-first ([part 15](15-benchmarks.md#mlperf-inference)). Picked at the owner's request, 21 Nov 2026; settled by BEN-01's smoke runs and the owner's review.
- [ ] **D-26 Verified results.** Open, the owner's decision: verified MLPerf results need MLCommons membership or a test-partner arrangement. Until then every published number is labelled "Result not verified by MLCommons Association." ([part 15](15-benchmarks.md#publishing-and-labelling)). Settled before BEN-08.

## Risks

| ID | Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- | --- |
| R-01 | **C is unsafe in practice.** A use-after-free or an overflow in a parser of model output, a web page or a protocol frame | Medium | High | The memory model removes most lifetimes ([part 03](03-memory-safety.md)); every parser fuzzed before it merges; sanitizers on every test; CBMC and Frama-C on the trusted side; the reviewer rules; the trusted side isolated so a bug elsewhere cannot authorize an action |
| R-02 | **A byte format drifts.** A float, an escape or a field order changes between builds or compilers, and a receipt or an audit hash no longer verifies | Medium | High | Golden vectors written independently of the C code, replayed on every pull request on every compiler; round-trip fuzzing of JSON and CBOR; versioned formats ([D-21](#decisions)); DATA-01 verifies history written by earlier builds |
| R-03 | **A module misses its budget.** Where the work is inside a shared library (SQLCipher, llama.cpp), PR3's share is small and hard to move | Medium | Medium | The budget row records the miss and its reason; an explained miss is accepted by decision ([part 15](15-benchmarks.md#module-budgets)) |
| R-04 | **The llama.cpp baseline is not stock llama.cpp.** Different build flags or backends make the comparison measure the build, not PR3 | Low | Medium | Fetched unchanged at b11429; flags recorded in every run's manifest and matched between the `llamacpp` and `pr3-llamacpp` SUTs; identical prompt tokens checked per sample |
| R-05 | **The engine is late or slow.** Qwen3.5's mixed attention and recurrent blocks, quantized kernels and GPU paths are a large body of work, and ggml is heavily tuned | High | Medium | The llama.cpp backend ships until the engine passes the same fixtures and beats it under LoadGen on a named device; the engine starts after M1 and runs in parallel; per-operation vectors from llama.cpp |
| R-06 | **Accessibility.** SDL3 has no screen-reader support; five bridges are a large, platform-specific job, and a gap blocks the app for users who rely on it | High | High | Accessibility is its own issue in M2 on the first two OSes (APP-04) and on iOS (APP-05), before the other screens; the tree is part of `pr3_ui` from the start; an OS's app release waits for its bridge, while the headless node can ship there first |
| R-07 | **Complex text and input.** Persian shaping, mixed-direction lines, IME composition and selection on SDL3 | Medium | High | HarfBuzz and SheenBidi rather than hand-written shaping; rendering fixtures with mixed text; APP-02 checked on physical devices |
| R-08 | **Encrypted stores differ across providers.** CommonCrypto and libtomcrypt builds disagree on a default and a database written on one OS does not open on another | Low | High | Cipher settings pinned explicitly, not inherited; DATA-02 opens databases written on every other OS; originals kept recoverable |
| R-09 | **Unicode semantics drift** between the generated tables and a platform's own (ICU, Foundation), changing what the trusted side accepts or what the UI shows | Low | High | The trusted side uses only the generated tables; exhaustive per-code-point tests against the UCD in CI |
| R-10 | **Bounded resources refuse real work.** Session eviction or a full history heap refuses a workload a user really has | Medium | Medium | Limits chosen from measured workloads in BEN-03; each limit an edge test in the ledger ([D-04](#decisions)) |
| R-11 | **Board budgets.** The ESP32-C3's Noise handshake, buffers and Wi-Fi stack exceed its RAM, or the Pico accessory exceeds 32 KiB | Medium | Medium | Budgets frozen before optimization; the gateway profile for any board that cannot hold keys; link maps and stack painting in CI from EMB-01 |
| R-12 | **MLPerf moves.** The LoadGen version, the Edge benchmark list or the rules change between rounds | High | Low | LoadGen pinned by commit; its version written into every run; a new round adopted by decision ([D-25](#decisions)) |
| R-13 | **An unverified number is read as an official one** | Medium | Medium | The labelling rules of [part 15](15-benchmarks.md#publishing-and-labelling) on every published number; a review of every public report against them (BEN-08) |
