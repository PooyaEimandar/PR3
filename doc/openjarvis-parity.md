# OpenJarvis capability and acceptance checklist

Upstream documentation reviewed 17 November 2026; PR3 implementation evidence updated 24 November 2026. This is the implementation checklist for the [roadmap](roadmap.md), not a claim that the products have reached parity. Upstream documentation describes supported features; PR3 acceptance requires working code and measured workflows on the current build. Existing benchmark archives remain historical evidence.

The [online-search repair](../bench/research/evidence/2026-11-20-online-repair-report.md) passed the reported 4B macOS request and offline continuation; its APK is the last documented Android installation. The latest [strict-quality evaluation](../bench/research/evidence/2026-11-24-research-strict-report.md) completes 240 reviewed turns on both models at seeds 1/2/7: **240 main passes, 236 strict and 240 lenient**. Development scores are 81/81 for both models; exposed scores are 39/39 for both. All 20 strict failures of the [22 November evaluation](../bench/research/evidence/2026-11-22-research-coverage-report.md) pass main and strict review; no new main failures were found. Four new borderline answers remain: two identity overstatements and two blurred temporal statuses. Four rejected attempts were repaired, none avoidable. All 84 restart snapshots and evidence checks pass without retrieval; restart answers pass 84/84 main and strict. The build passes 511 workspace tests plus four native tokenizer/grammar checks and all 49 archive-verifier controls. This exposed implementation-assistant review is not independent validation or a new matched upstream comparison. Live/native UI and Android acceptance remain open.

## Finish research first

| Gate | PR3 implementation | Evidence still needed |
|---|---|---|
| Reliable bounded research | Fitted coverage plans require complementary source facts; checked quotations replace unsupported factual restatements; required-read grammar and cautious identity repair preserve existing budgets; source conditions, continuation and corrections survive restart; exact quotations and source/task/deletion checks remain active | [Latest source review](../bench/research/evidence/2026-11-24-research-strict-report.md): 240/240 main, 236 strict, 240 lenient; restart answers 84/84 main and strict. All 20 preceding strict failures pass; no avoidable validator repair. Identity and temporal wording slips recur in new forms (four borderline answers). Live/native/Android acceptance, controlled latency and fresh independent review remain |
| Unified chat and source choices | Natural research requests in the same chat/task; inline Web and Sources controls; ordinary tools return on later turns; candidate, redirect, snapshot, inference and citation checks; corrections can narrow the scope | Physical Android acceptance, broader routing/language evaluation, live redirect edge cases and broader provider coverage. “Official” is not inferred from a page title; the user selects the relevant websites |
| Useful document ingestion | Text/Markdown snapshots and FTS search | Bounded PDF extraction next; DOCX/OCR, folder indexing, incremental updates and document versions afterward |
| Retrieval quality | Exact local full-text retrieval; bounded lexical page-part selection across long sources; context-preserving excerpts | Semantic/multilingual retrieval and larger-library tests; compare native retrieval with upstream, not only the shared tool adapter |
| Research output | Inspectable saved quotations, model-written conclusions for selected inference questions, and gaps | Concise relevance and requested-language quality; one approved local export, such as a sourced note, with a verified write result; exact quotations alone do not prove a conclusion |
| Continuity | Local restart, pairing, task/memory ownership and deletion transport | Physical Android↔computer acceptance, source transport, interrupted transfer, deletion convergence and replacement-device recovery |

Enable **Web** in the chat composer, then open **Sources** and use **Only these websites** for 1–4 comma-separated domains, for example `sqlite.org, docs.example.org`. Subdomains are included; local documents and other websites are excluded. The equivalent typed request ends with `Sources only: sqlite.org`. Later user messages or field choices can narrow this list; clearing the field does not broaden it, and a fresh task is required to broaden it. Scope comes from actual user messages and controls, never source text. Ambiguous English official-only requests ask for websites instead of treating search-result labels as proof. This is an explicit domain restriction, not general multilingual authority classification. Web starts off after restart or task switching; saved evidence remains available.

Inference uses short `s:` source references and optional opaque `q:` excerpt references. Each excerpt reference binds the range, exact text and source identity through a checksum; guessed ranges and references copied to another source fail. A citation can supply the excerpt reference alone: the report tool resolves it only within this task's bounded, live, permitted evidence. An explicitly supplied source must match; there is no fallback for a mismatched pair. The tool verifies UTF-8 boundaries and quotation limits, and emits the full canonical provenance. These references grant no access and cannot recover deleted sources. A bounded report-quality guard rejects recognizable unrelated commands addressed to the assistant; it is not a general semantic relevance or entailment checker. Existing approval checks and the four-round/twelve-call limit remain active.

Each inference quotation keeps its source, excerpt reference, offset and exact text together. Optional anchors cross-check the selected quotation rather than selecting a substitute. Factual findings use checked quotations directly; a coverage plan is recomputed after fitting and tracks requested concepts separately for each source. Selected inference questions retain conclusions. A real identity-validation failure can restrict its next conclusion to cautious uncertainty within the original budget; source text cannot activate that repair. Conservative checks target strong lexical mismatches, false literal source attribution and explicit past-year current-validity contradictions; negative subjects and contractions remain valid. Current-fact requests retain the runtime date after context trimming. An unambiguous ellipsis error can suggest an exact excerpt reference for an explicit retry, within the original budget. Requested source-instruction inspection receives a runtime-owned authority notice. These changes strengthen report validation; they do not prove all generated interpretations, completeness or general temporal reasoning.

Acceptance sequence: deterministic regressions → complete 4B/27B development and separately frozen generalization runs → all-answer review → live macOS Tavily workflow with source inspection and restart → user-run Android checklist → controlled-power timing and independent review. The current fresh set is now exposed; future new generalization claims need a new frozen set. Preserve the exposed v1 corpus and results as regression history. The earlier matched comparison measures orchestration over common tools, not native search or complete product parity.

## Broader gaps after research acceptance

These follow research; they are not prerequisites to calling a single document workflow useful.

| Upstream capability | PR3 gap | Completion gate |
|---|---|---|
| Scheduled and continuous agents | Durable scheduler, background execution, bounded retries and notifications | A user-created monitor survives restart, reports only verified changes, stops on request and never gains action permission from a schedule |
| Skills and tool composition | Versioned, permission-scoped skill catalog and execution | A reusable research skill uses the existing core, preserves source trust and execution limits, and supports revocation; imported scripts do not run automatically |
| Code assistant | Sandboxed code/file tools | Explicit workspace selection, isolation, resource limits, review of consequential changes and recovery; unrestricted shell access is not a parity shortcut |
| Engine breadth and routing | Additional backend interfaces, device-specific capability selection | Matched quality/latency/energy measurements establish when routing helps; private content never silently goes to a cloud provider |
| Learning from traces | Opt-in trace evaluation, skill/policy optimization and rollback | A frozen evaluation shows a gain without weakening permissions or privacy; failed updates roll back |
| Distribution and operations | Release hardening and some platform key custody | Signed releases, recovery testing, refreshed security matrix, independent review and a completed usefulness trial |

Email/contacts remain retired and the unified social inbox remains deferred by the product decision. Upstream connector breadth is recorded as a difference, not authorization to restore those features. Mobile source continuity is a PR3 acceptance goal; upstream's own roadmap still lists federated memory as active work.
