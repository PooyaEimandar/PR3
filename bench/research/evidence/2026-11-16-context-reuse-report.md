## Implementation

- Build a transient inference view from the current task's SQLite source records on every generation. Earlier reports do not validate a new answer. Recent user wording and the current request remain distinct, so the protected continuation does not repeat all remembered context.
- Select exact source excerpts with byte offsets, preserving separate requested facts in separate fields. Keep complete immutable snapshots for citation validation and source inspection. Explicit source reads retain priority; an optional byte offset recovers omitted text without a new fetch.
- Fit the complete protected prompt with the real tokenizer, reserving the existing answer allowance. Only host-marked tool evidence can be excerpted; the current user request, trusted policy and execution-budget notices are not clipped. Oversized user requests still fail closed.
- Replace duplicated successful page bodies with receipts. During report repair, omit rejected draft arguments from inference while retaining the failure and the core's actual calls/counters. Empty inventory queries never retry a failed search provider.
- Keep evidence untrusted. Quotations must match an existing task-owned saved source exactly; deleted, foreign, fabricated or shortened IDs still fail validation. No consequential action is authorized by research.

Deterministic regressions cover warm continuation, SQLite close/reopen, corrections, task isolation/deletion, Unicode offsets, sparse facts in a long page, source-role spoofing, invalid quotations, provider retry avoidance, and both successful repair and exhaustion of the unchanged four-round budget.

## Evidence and limits

The [per-turn summary](2026-11-16-context-reuse-summary.json) retains every final result, including the failure. The [raw final traces, generated corpus and SHA-256 manifest](2026-11-16-context-reuse.tar.gz) provide the underlying records. The production Host and local llama.cpp adapter used `Qwen3.5-4B-Q4_K_M`, seeds **1/2/7**, with unchanged limits: 4 tool rounds, 4 calls per round, 12 calls per turn, 4 KiB arguments, 8 KiB tool output, 4,096 context tokens and 512 generated tokens per pass.

The new fixtures are generated by [context-regressions.ts](../context-regressions.ts); the existing [quotation regressions](../quotation-regressions.json) were unchanged. These are development cases used while fixing the implementation, **not a frozen held-out evaluation**. Earlier exploratory runs exposed sparse-fact selection, metadata quotation and rejected-report overflow problems; the final matrix above includes their fixes. The historical v1 corpus, comparison and live acceptance evidence were not rewritten.

Restarted turns had a median of **5.43 seconds** (range **3.13–27.99 seconds**). These timings are diagnostic: background checks/builds ran on the Mac, and power was not controlled. They are not a speedup claim against the previous live-page test or OpenJarvis. Source IDs contain task timestamps, so a seed alone does not make these development replays byte-identical.

This run used synthetic offline page fixtures. It did not read the user's Tavily key, access private chats, rerun 27B, or establish native macOS/Android live acceptance. Next checks are live Tavily and Android; remaining implementation work includes complete citation-ID copying, planning within the current limit, explicit source restrictions and broader temporal/conditional reasoning.

## Reproduce

From the repository root, choose fresh output paths:

```sh
node bench/research/context-regressions.ts /tmp/pr3-context-cases.json
cargo build -p pr3-bench-documents --bin research
target/debug/research model/Qwen3.5-4B-Q4_K_M.gguf 1 /tmp/pr3-context-cases.json /tmp/pr3-context-seed1.jsonl
target/debug/research model/Qwen3.5-4B-Q4_K_M.gguf 1 bench/research/quotation-regressions.json /tmp/pr3-quotation-seed1.jsonl
cargo test -p pr3-llamacpp --lib actual_token_budget -- --ignored --nocapture
```

Repeat the two model commands at seeds 2 and 7. Inspect every row's `pass` and every turn's checks: the diagnostic runner writes failed rows and does not use the process exit code as a content-quality verdict.
