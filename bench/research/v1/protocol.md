# Research comparison v1 — preregistered protocol

Freeze the 16 held-out scenarios, two separate smoke scenarios and production source hashes before any model inference on the new corpus. Each scenario has a distinct synthetic family. Category overlap with earlier development cases is intentional; this is a public runtime holdout, not independent authorship or proof of model-training independence. No user documents, credentials or live sites are in the corpus.

Scope: Qwen3.5-4B-Q4_K_M and Qwen3.8-27B-Q4_K_M, seeds 1/2/7, PR3 Host and the pinned actual OpenJarvis `OrchestratorAgent` in function-calling mode. Sixteen scenarios × two models × three seeds × two arms = **192 scenario runs**. Four scenarios have an offline resumed turn: **240 turns**. Smoke cases are excluded from these totals and all held-out scores. Harness faults may be fixed using smoke cases; production prompts, budgets and held-out oracles must not be tuned after freeze. Any invalidated run must be retained and labeled, not overwritten.

Both arms use the same model bytes, llama.cpp build and settings, research tool definitions, encrypted-storage-independent synthetic SQLite snapshots, original web topic, fixed search results and page contents. Model-generated queries remain local. Search-provider failures and offline restart are fixtures. Only the three read-only research tools are available. No action connector, added approval authority or changed production execution allowance is introduced. Common limits: four tool rounds, four calls per round, twelve calls per turn, 4 KiB arguments, 8 KiB tool output; existing report/source limits apply. Five outer inference rounds allow the final answer after four tool rounds. Both use the shared engine's read-only/report metadata and protected report-argument path. Extra internal inference passes are measured rather than described as free work.

OpenJarvis uses its upstream loop and a fixed research-role prompt adapted from its research example to the shared tool names. Parallel tools are disabled because the common bridge is sequential. This compares orchestration over shared source retrieval and verification. It does **not** compare OpenJarvis's native retrieval stack, full application persistence, larger tool ecosystem or broad security. PR3 keeps its shipped research prompt and Host behavior. The original small NativeReAct document comparison remains separate.

For restart, close/reopen the actual shared SQLite storage, reconstruct the Host/upstream agent, and disable fixture network access. PR3 restores its task; the upstream adapter restores the saved user/assistant transcript through `AgentContext`. Model weights stay loaded. This is source/task recovery under the shared adapter, not process-cold model startup or proof of native OpenJarvis cross-device behavior.

Scoring separates required facts, authentic source quotations, explicit reasoning checks, forbidden answer content, successful report-tool use and runtime errors. Facts cannot be supplied by fingerprints, filenames or source URLs. Distinct passages of the same document do not count as independent sources. Requested instruction inspection and unrelated injected instructions have different checks. Literal/regex requirements are diagnostic; they do not prove general semantic entailment. Preserve every final answer, tool result, raw generation, trace, saved source and network event for independent replay. Keep errors and missing turns in denominators; reject duplicate/foreign rows. No automatic retries of failing cases.

After inference, create an answer/source review packet with arm/model labels hidden. Review each conclusion against the frozen scenario rubric, especially contradictions, causation, temporal qualification, abstention and latest-request relevance. Record review decisions and explanations separately from deterministic scores. The implementer is not an independent blinded reviewer; do not claim that level of independence. A report without completed review must label synthesis quality unassessed.

Performance: alternate agent order, run sequentially on the same Mac, record hardware, power state, model/binary/source hashes, engine token counts and elapsed time. Exclude model loading from warm-turn timings; retain bridge/adapter wall time separately. Report per-model/arm median and p95 together with errors and answer quality. Do not run concurrent model workloads or the live app during timed comparison. These measurements cannot establish Android performance or energy efficiency. Live Tavily acceptance is a separately documented app test using a user-entered key and public topics; it is not repeatable frozen benchmark input.
