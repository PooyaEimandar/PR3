## What this establishes

The shipped document path can search these small text/Markdown fixtures and return exact, inspectable quotations. It rejected truncated/invented source IDs and recovered within the existing bounds where the model retried. The shared-tool experiment measures orchestration and the final verification contract; it does **not** measure OpenJarvis’s own indexing/retrieval stack, overall product quality, full security, or superiority on realistic large collections. These are public development cases, not held-out evidence.

## Build and scoring integrity

OpenJarvis is pinned to [`76836f4eba5e`](https://github.com/open-jarvis/OpenJarvis/commit/76836f4eba5e0d25cf53b56c2f475a2c2583c1c9). The model SHA-256, binary SHA-256, evaluated Rust source hashes, hardware and sampling configuration are in the manifest. The model uses 4,096-token context, 512 tokens per engine pass and the shared ceilings described in the [harness](../README.md). PR3's protected answer pass is additional recorded work, not free inference.

No prompts or planning policies were tuned during the run. Final runtime hardening restored false-completion detection for unsupported actions and extended document answer checks beyond the display's source/ancestor limits; all **36/36** recorded PR3 model traces were then replayed through the final Host/document tools with byte-identical final answers. Replay uses no model and is not an independent model sample. The original evaluated sources and the final sources/hashes/replay evidence are retained as separate overlays on the manifest's base Git revision.

Scorer v1 wrongly treated an accurately quoted hostile-looking filename as an emitted attack marker. Scorer v2 exempts the actual complete filename while still rejecting the standalone marker; a regression test covers both. This changes OpenJarvis workflow completion from **19/36 to 21/36**, leaves factual checks unchanged, and preserves all v1 raw scores/replies. Zero forbidden markers in v2 is a narrow answer check, not evidence about unauthorized actions: neither arm has an external action connector in this experiment.

## Timing and limits

Observed median end-to-end workflow time, excluding model load: PR3 **10.03s**; OpenJarvis **8.27s**. These are diagnostic desktop observations: some builds/tests overlapped, power/thermal conditions were not controlled, and the output policies do different amounts of work. Do not infer a latency or efficiency ranking; Android remains unmeasured.

Next evidence should cover longer real documents, version conflicts, PDF extraction, broader languages, independent retrieval backends and a fresh frozen held-out set before tuning or making a competitive claim.
